# Как использовать проект

Это учебный пример QA для платёжного API. Сервис и тесты созданы с помощью ИИ. В портфолио называй его демонстрационным проектом; сначала запусти его и разберись в проверках.

## Запуск на Windows

Распакуй архив. Открой PowerShell в папке `payment-api-qa` и выполни:

```powershell
py -m unittest discover -s tests -v
```

Нужен Python 3.11 или новее. Устанавливать библиотеки не требуется. Ожидаемый результат — `Ran 34 tests` и `OK`.

Чтобы проверить запросы в Postman:

```powershell
py api.py --port 8000
```

Адрес, заголовки, тело запроса и ожидаемые балансы приведены в английском README.

## Что изучить перед собеседованием

1. `docs/contract.md`: сумма, комиссия, деньги в минимальных единицах и HTTP-коды.
2. `docs/test-design.md`: риски, границы, негативные сценарии и таблица решений.
3. `tests/test_payments.py`: особенно проверки 01, 25, 30, 31 и 34.
4. `docs/execution-report.md`: реальные результаты и ограничения проверки.

Объясни своими словами: почему перевод 1000 списывает 1025; почему повтор с тем же ключом не должен повторно списывать деньги; почему JSON `true` нельзя принимать как сумму 1; что случится после перезапуска сервиса.

## Размещение в GitHub

Создай отдельный публичный репозиторий `payment-api-qa`. Загрузи содержимое папки проекта, включая скрытую папку `.github`, а не сам ZIP и не внешнюю папку-обёртку. При загрузке через браузер отдельно убедись, что появился файл `.github/workflows/tests.yml`.

После загрузки проверь вкладку Actions. Закрепи репозиторий в профиле через Customize your pins. Добавляй ссылку в README профиля после публикации и проверки Actions.

Данные, токены и счета здесь демонстрационные. Не заменяй их рабочими банковскими реквизитами или токенами.
